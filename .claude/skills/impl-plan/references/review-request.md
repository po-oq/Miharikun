# 計画のレビューの依頼文（別セッションに貼る）

【】を埋めて、チャットにコードブロックで出す。利用者がそのまま別セッションに貼れるように、1 つのブロックにまとめる。

```
【出力先】/【名前】-plan.md（図解は 【名前】-plan.html）をレビューしてください。
仕様の正は 【仕様の文書】 の 【章・フェーズ】、設計の資料は 【設計の資料】。
実コード（【計画が変更・流用する主なファイルを列挙】）と突き合わせ、
特に ①【共通化で既存の挙動が変わらないか】 ②【共有する資源の方針の妥当性】 ③【7 章の分かれ道・タイミングの抜け】 ④【状態の表の抜け・矛盾】 ⑤【失敗の経路でデータを失わないか】 を見てください。
結果は 【出力先】/【名前】-review.html に、問題ごとの根拠（file:line）と解決策つきでまとめてください。コードは変えないでください。
```

- ①〜⑤は、計画の 7 章（迷いやすい所）と 8 章（リスク）から、危ない順に選ぶ。
- 計画・設計の資料・仕様の変更が未コミットなら、「別の作業ツリー（worktree）や別の環境のセッションでは見えない。同じフォルダで開くか、先にコミットする」と添える。
- レビューが返ってきたら、鵜呑みにせず、指摘ごとに実コードで事実を確かめてから採否を決める（採らないものは理由を利用者に説明する）。採ったものは **md と HTML の両方**に反映し、末尾の状態を「確定（レビュー反映済み）」にする。
