Q1.（#2） 受け入れた後に「書き方だけ違う」登録をどう扱うか
A) GetState の一致を「exe のパスの正規化した一致＋--agent cursor あり」に変える … 利点：手で書いた動く登録をそのまま使え、ダイアログが出ない／欠点：GetState を変えるのでテストを足す（既存は通る見込み）
B) GetState は変えず、受け入れた後の Partial で「登録の書き方を直します（場所は C:\dev）」を 1 回提案する … 利点：GetState に手を入れない／欠点：会社の PC で最初にダイアログが出る。「いいえ」なら毎回出る
推奨：A（受け入れの目的は「動いている登録を、ダイアログなしで正とする」こと。--agent cursor の有無だけは動くかに関わるので見る）
Q2.（#7） Hook の登録の時刻が変わったとき、読み済みの transcript を判定し直すか
A) ポーリングのたびに hooks.json の更新日時を stat し、変わったら全部読み直す … 利点：「hook を削除」・手での書き換え・導入がすぐ反映、帯が残らない／欠点：変わった回だけ全件を読む（まれ）
B) 今の計画どおり、読み直した回だけ … 利点：簡単／欠点：削除しても再起動まで帯が残る
推奨：A
Q3.（#4） 最後の行の扱い
A) 改行で終わる、または JSON として読めれば使う … 利点：Cursor の書き方に左右されない／欠点：ほぼ無い（書きかけでたまたま読める JSON はまれ）
B) 改行で終わるときだけ使う（計画のまま） … 利点：単純／欠点：Cursor が最後に改行を付けない形式だと、最後の返事がずっと出ない
推奨：A（Cursor の形式を確かめてから B にしてもよい）
