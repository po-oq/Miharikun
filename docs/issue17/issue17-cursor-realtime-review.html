6. リスクと対策

リスク対策
transcript の監視で、チャット中に何度も取り込み直して重くなる変わったファイルだけ読む（長さ・更新日時で判断）。デバウンスは既存の 300ms を共用。大きい transcript の計測は PerfFact で
Hook の記録と transcript の取り込みが同じ ID で二重に出る今の「Hook の記録がある ID は取り込まない／現れたら取り込み分を Remove」（CursorSessionSource.cs:221-232）を、毎回の取り込みでも守る。テストで確認
「Hook が記録していない」の誤検知（導入直後の数秒など）hooks.json の導入日時より後に更新され、かつ一定時間（例：1 分）経っても events が無い transcript だけ数える
Cursor の transcript の形式は公開仕様ではない今の取り込みと同じく、読めない行は飛ばす。Cursor のフォルダには書かない
