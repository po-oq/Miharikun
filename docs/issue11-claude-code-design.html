状態：確定（Q1〜Q8・N1〜N4 に回答済み。12 章）。要件定義に反映済み。

ゴール：このプロジェクトを進めている Claude Code（CLI と Code タブ）のセッションを、Cursor と同じ一覧で見られるようにする。まず「成果（コミット・テスト実行）がどう見えるか」を確かめられることが目的。
データは会話ログを読むだけ（フックなし）。根拠は Step 0 の結果（Issue #11 のコメント）。

1. 画面イメージ

変わる所：①カードと詳細ヘッダーにエージェントのバッジ（Cursor / Claude）②左ペインにエージェントの絞り込み（全て / Cursor / Claude）。それ以外の画面（詳細・タイムライン・メモ・ステータス・ドキュメントタブ）は、共通イベントだけを見ているので、そのまま使える。
取れない項目は出さない（Claude に無い「閉じた」状態、など。Capabilities で切り替える）。

2. データの流れ（概念図）

ご指摘のとおり、ProjectEventStore と ClaudeSessionStore は同じ役割（プロジェクトのセッションのイベントを保持し、追記を取り込み、変わったセッションを知らせる）。違うのは「どこから・どんな形式で読むか」だけ。
そこで、保持・要約のキャッシュ・変更通知は 1 つの汎用 ProjectEventStore に集め、読み込みの部分だけをエージェントごとの ISessionSource（CursorSessionSource / ClaudeSessionSource）に切り出す。別のエージェントを足すときは、Source を 1 つ足すだけになる。

この形にする利点：①汎用 Store は 1 つで、テストも 1 回で済む ②SessionMonitor は Store を 1 つ持つだけで、複数エージェントの合成（composite）が要らない ③Cursor の「Hook があれば transcript より優先」のようなエージェント固有の事情が Source の中に閉じる ④今後 Codex などを足すときも、Source を 1 つ書くだけ。
あなたの案（CursorSessionStore と ClaudeSessionStore を並べ、ProjectEventStore を抽象にする）との違いは、Store をエージェントごとに作らず、Source だけを分ける点。保持・キャッシュの処理を 2 か所に書かずに済むため。名前は「Cursor / Claude の SessionSource」にした。

5. プロジェクトとの対応づけ

  • 会話ログを探す場所：%USERPROFILE%\.claude\projects\ の下で、フォルダ名が「対象フォルダの Claude 式の名前」（C:\zDev\repo\Miharikun → C--zDev-repo-Miharikun）と同じ、または、それに --claude-worktrees- が続くもの。
  • 見つけたフォルダの中でも、各ファイルの最初の記録の cwd を既存の ProjectPath で照合する（フォルダ名の規則の違い・日本語や記号の違いに頼らない）。作業ツリーは、cwd が「対象フォルダ\.claude\worktrees\名前」のものを同じプロジェクトとして扱う。
  • 検証用の環境変数 MIHARIKUN_CLAUDE_DIR（既定は %USERPROFILE%\.claude）を足す（MIHARIKUN_CURSOR_DIR と同じ流儀）。
  • 初回は全ファイルを読む（最大 20MB。背景で）。以後は追記分だけ（既存の JsonlTail）。このとき、いま書き込み中の最終行（不完全な行）は次回に回す（既存と同じ）。

リスク対策
会話ログの形式は公開仕様でなく、バージョンで変わる知らない行・壊れた行は飛ばす。version を記録。ログに警告を残す。変わったらテストで気づけるよう、フィクスチャを実ログの構造に合わせる

会話ログに会話の全文・機密が入っているMiharikun はローカルで読むだけ。外に出さない。テストのフィクスチャは実ログのコピーを使わず、手書きにする
