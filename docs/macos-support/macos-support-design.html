0. 結論（先に）

おすすめ：案 A「画面を Avalonia 12 で作り直し、Windows と mac で同じ画面を 1 つにする」

  • いまの部品（3 ペインと分割バー・ツリー・仮想化した一覧・折りたたみ・タブ・右クリックメニュー）が Avalonia にそろっていて、画面の配置はそのまま再現できる。
  • プレビューの要の WebView が、Avalonia 12 から MIT の標準部品（NativeWebView）になった。Windows は WebView2、mac は WKWebView（OS に最初から入っている）を同じ書き方で使える。リンクの振り分けに要るイベント（NavigationStarted の取り消し・NewWindowRequested）もある。
  • C# と MVVM（CommunityToolkit.Mvvm）のまま。Core 約 5,500 行・Docs・Hook・テスト 842 件はそのまま使える。「App は AgentEvent だけを扱う」「Core は AOT 互換」の決まりも崩れない。
  • 書き直すのは画面（XAML 約 1,400 行と画面まわりの C# 約 1,100 行）。規模は中〜大（7 フェーズ程度。メモタブの 2 倍弱）、難易度は中。

Windows でしか動かないのは、ほぼ画面のプロジェクト（src/Miharikun/）だけ。Core・Docs・Hook のコードは OS に依らない書き方になっていて、直すのは数か所。

7. 署名なしで配る（Q3-B）のしくみと手順

7.1 なぜ止まるのか、どう開くのか

  • 「隔離」の印（com.apple.quarantine）は、ブラウザなどがダウンロードしたファイルに付ける目印。印の付いたアプリを初めて開くとき、macOS（Gatekeeper）が「Apple に登録した開発者の署名」と「Apple の公証（マルウェア検査）」を調べる。どちらも無いので止まる。
  • アプリの中身が壊れているわけではない。止まるのは「印がある＋公証が無い」ときだけで、印を消すか、利用者が「開いてよい」と許すと、ふつうに開ける。
  • macOS 15（Sequoia）以降は、以前の「Control キーを押しながらクリック → 開く」では開けなくなった。いまはシステム設定から許すか、ターミナルで印を消すかの 2 つ。

7.3 配る側（CI）でやること

#やることなぜ
①GitHub Actions の macOS ランナー（macos-latest）で、App（自己完結）と Hook（NativeAOT）を osx-arm64 で発行し、Miharikun.app にまとめる。Hook は Miharikun.app/Contents/MacOS/Miharikun.Hook に入れる配る物を 1 つにして、やり方 1 の 1 行で Hook までまとめて許せるように
②codesign --force --deep --sign - Miharikun.app（アドホック署名。証明書もお金も要らない）Apple Silicon は、署名の無いプログラムをそもそも動かせない。署名が崩れた .app は「壊れているため開けません」と出て、7.2 の「このまま開く」の道も使えなくなる。アドホック署名は「中身が改ざんされていない」ことだけを示し、Apple の公証の代わりにはならない（だから印の解除は要る）
③zip は ditto -c -k --keepParent Miharikun.app ….zip で作る実行の権限と署名を壊さずに固めるため（Windows の Compress-Archive で作ると、実行できない .app になる）
④zip の SHA-256 を Release に添える（….zip.sha256）印を消す前に、ダウンロードした物が Release の物と同じか確かめられる
⑤アプリの「Hook の導入」で、コピーした Hook の印を消し、試しに 1 回起動して確かめる。だめなら、README のやり方 1 の 1 行を画面で案内するやり方 2 で開いた人でも、Cursor から呼ばれた Hook が止められないように。止められると、Cursor の記録が黙って残らない（要確認：Phase 27 で、印つきの Hook を Cursor が呼ぶとどうなるかを見る）
