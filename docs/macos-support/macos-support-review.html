Q1.（決定：A）並べ替えで選択が外れる（#1）
どういうときに、どうなるか（Avalonia 版＝Phase 30 から。今の WPF 版と、WPF のままの Phase 28 では起きない）：
・左の一覧は「最後の動き」の新しい順。セッションに動き（依頼・返事・ツールなど）が来ると、そのカードが一番上へ移る。
・起きるのは、見ている（選んでいる）カードに動きが来て、そのカードが上へ移るとき。例：Cursor のセッション A（上）と Claude Code のセッション B（下）を並行して動かしていて、B を見ている → B に返事が来る → B が A の上へ移る。
・このとき Avalonia の一覧は、B を選んでいたことを忘れる → 左の選択の色が消え、中央の詳細と右のタイムラインが空になる。拡大していれば元に戻り、タイムラインの検索語・スクロール位置も消える。B をもう一度押すまで空のまま。次に B が上へ移ると、また起きる。
・起きないとき：見ているカードがすでに一番上にあるとき（位置が変わらない）。ほかのカードが上へ来るとき（動くのはそのカードの方）。
・原因：Avalonia の一覧の部品は「移動」を「いったん取り除いて足し直す」として扱い、取り除いた項目の選択を外す（Avalonia の未解決の不具合。WPF は選択を保つ）。
選択肢：
A) 並べ替えるとき、見ているカードは動かさず、ほかのカードを前後に動かして同じ並びにする（一覧の部品から見ると、選んだカードは動いていない）。念のため、それでも「選択が外れた」と来たら、アプリ側で無視して選び直す保険も入れる（ただし、絞り込みで隠れたときは選び直さず外す） … 利点：今の WPF と同じ見え方。テストで確かめられる／欠点：並べ替えのコードが少し複雑になる
B) 並べ替えは今の計画のまま。選択が外れたら、アプリ側ですぐ選び直す … 利点：並べ替えのコードは単純／欠点：選択の色が一瞬消えて付き直す（ちらつく）。一覧のスクロール位置やキーボードのフォーカスが動く恐れ
C) Avalonia の不具合（#16279・#17819）が直るのを待つ … 欠点：いつ直るか分からない。それまで上の症状が出る
推奨：A（B の保険も一緒に入れる。30-3 の Avalonia.Headless のテストで、並べ替えても選択が残ることを確かめる）
