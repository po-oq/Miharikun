Issue #23：Claude Code のセッションタイトルをカードに出す

状態：確定（Q1〜Q3 は推奨どおり。2026-10-08）。

ゴール：Claude Code のカード・詳細のタイトルを、「最初の依頼の先頭 40 文字」でなく、Claude Code 自身が持つセッションのタイトル（会話ログの custom-title）にする。Cursor は変えない。

1. 調べた結果（事実）

対象結果根拠
Claude Code取れる会話ログに {type:"custom-title", customTitle, sessionId} の行がある。手元 29 本中 21 本（版 2.1.197〜2.1.293）。冒頭（10〜50 行目）に入り、その後も同じ値で繰り返し追記される。この 21 本では 1 本につき値は 1 種類。ai-title は 0 件。行の項目は type・customTitle・sessionId のみで、timestamp は無い（確認済み）
Cursor取れない（方針上）Hook の payload にタイトルの項目なし。agent-transcripts の行は role/message だけ。チャット名の置き場は state.vscdb と思われる（読み書きしない決まり。確認もしていない）

4. 変更点

場所いま変更

6. 設計の細部（回答済み：すべて推奨 A）

Q1. タイトルの運び方
A) 新しいイベント種別 TitleChanged … 共通イベントだけを扱う原則（5.1）に合い、他の Source にも使える。種別を足すので switch の洗い出しが要る
B) 既存のイベントに Title 項目を足して載せる … 種別は増えないが、どの行に載せるか（timestamp の無い行）が不自然
推奨：A
Q2. custom-title の行に timestamp が無いときの時刻
A) 直前の timestamp を使う（最終活動時刻はずれない） … 先頭より前に来た行は出さない（その後の繰り返しで拾える）
B) 取り込んだ時刻（現在） … 最終活動が「いま」になってしまう
推奨：A
Q3. 長いタイトルの扱い
A) 切らずにそのまま出す（カード側で省略表示） … 実データでは 15 文字程度で短い
B) 40 文字で切る … 既存と揃うが、利用者が付けた名前を欠く
推奨：A

7. リスクと対策

リスク対策
会話ログは非公開仕様。custom-title が将来変わる・消える無い・壊れた行は今まで通り飛ばし、③（最初の依頼）に戻る。項目名が想定と違えば app.log に種類と件数だけ書く（本文は書かない）
新しい種別を足して、タイムラインや件数、状態判定に紛れ込むCore のテスト先行：TitleChanged が入っても状態・件数・最終活動・タイムラインが変わらないことを確認
実ログに ai-title など別の種類が出る今回は custom-title のみ（実物で確認できたものだけ）。ai-title は実物が出たときに足す
実機のログを引用してしまうフィクスチャは構造を真似て手書き。実ログのコピーはしない
