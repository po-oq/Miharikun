メモタブ 設計イメージ（コードを変える前の確認用）

いまはプレースホルダーのメモタブを、プロジェクト単位のメモ帳（Markdown）にする。表示はドキュメントタブの md プレビューと同じで、ふだんはプレビュー、「編集」を押すとエディタに切り替わる。

WPF には HTML の <textarea> にあたる専用のコントロールはなく、TextBox に AcceptsReturn="True"（＋ TextWrapping・縦スクロールバー）を付けたものが複数行の入力欄になる。書式を付けて書く RichTextBox もあるが、Markdown をそのまま書くので要らない。

3. 部品の構成（概念図）

  • プレビューの共通化：いまの DocumentPreview は DocumentsViewModel 専用。WebView2 の準備・未導入の案内・md の描画・リンクの振り分けを、ドキュメントとメモの両方で使える形に切り出す。WebView2 の作業フォルダ（webview2\）は共用（同じ設定なら 2 つ目の WebView2 も同じ環境で動く）。
  • WebView2 の上に WPF の要素を重ねない（12.7 のルール）：エディタとプレビューは重ねずに Visibility で入れ替える。ボタンは WebView2 の外（上のバー）に置く。
  • md の基準フォルダ：対象フォルダ（プロジェクトのルート）。メモに [説明](docs/release.md) や ![](docs/img.png) と書けば、そのまま効く。
  • Core の新規：ProjectMemoStore（パスを決める・読む・アトミックに書く）。テストを先に書く。

4. 保存先（案）

場所よい点気になる点
A（推奨）%LOCALAPPDATA%\Miharikun\projects\{slug}-{hash8}.memo.md
（プロジェクト設定の json と同じ名前に .memo.md）		中身がただの md なので、エディタで直接開ける・バックアップしやすい。json の中に長文を入れずに済む。既存のプロジェクト判定（6章）をそのまま使えるリポジトリには入らない（共有されない）
Bプロジェクト設定の json の memo キーファイルが増えない改行がエスケープされ、外から読みにくい。ドキュメントの設定の保存と同じファイルを奪い合う
C対象フォルダの中（例 .miharikun\memo.md）git で共有できる利用者のリポジトリに書き込む。.gitignore の判断が要る

書き込みは一時ファイル → 置き換え（既存の AtomicFile）。複数起動の競合は後勝ち（6章と同じ）。ほかのプロセスがファイルを書き換えたら、プレビュー中なら自動で読み直す（編集中は上書きしない）。

5. 決めたこと（2026-10-04：Q1〜Q8 はすべて案のとおりで確定。要件定義 12.10 に反映）

Q1. 保存先：A（アプリのデータフォルダに md ファイル）でよいか。B・C がよければそちら。
Q2. プレビューの中のリンク：ドキュメントタブと同じく ①http → 既定ブラウザ ②対象フォルダ内の md/html → ドキュメントタブに切り替えて、そのファイルを開く（案）③それ以外 → 既定のアプリ。②は「既定のアプリで開く」でもよい。
Q3. 未保存のままアプリを閉じたとき：確認ダイアログ（保存／保存しない／キャンセル）を出す案。セッションのメモのように「黙って自動保存」がよければそちら。
Q4. キャンセルで入力を捨てるとき：変更があれば「変更を捨てますか？」と確認する案。確認なしで即戻る、でもよい。
Q5. キーボード：Ctrl+S で保存を付ける案。Esc でキャンセルは、うっかり消しやすいので付けない案。
Q6. メモは 1 プロジェクト 1 つでよいか（複数のメモやフォルダ分けはしない）。
Q7. ダッシュボードの全文検索：プロジェクトのメモは対象にしない案（検索はセッションを探すためのもの）。
Q8. 空のとき：プレビューに「メモはまだありません。右上の『編集』で書けます」と出す案。

6. やらないこと

  • プレビューとエディタの左右同時表示、入力しながらのリアルタイムプレビュー
  • エディタの Markdown の色付け・補完・ツールバー（太字ボタンなど）
  • 履歴・元に戻す（保存前の Ctrl+Z は TextBox の標準のまま効く）
  • プレビューのチェックボックスをクリックして md を書き換える（ドキュメントと同じく読み取り専用）
