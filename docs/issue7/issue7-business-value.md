# Issue #7 壁打ち：Miharikun で業務は便利になったか

- 日付：2026-10-08
- 対象：会社での Cursor の使い方（家は Claude Code）
- 結果から作った Issue：#27（検索）、#28（ドキュメントの拡大モード）、#29（README の起動方法）

## 業務の前提（会社）
- 実装中は Cursor の IDE を 1 つだけ開き、セッションは同時に 1〜2 個。FE と BE は別々に作って動かし、両方開くのは接続テストでバグを探すときだけ
- Cursor の画面は「エクスプローラー 1 割・エディタ 7 割・チャット 2 割」。エディタで実装を見ながらチャットするので、チャット欄は狭く、タブは 2 個くらいしか並ばない
- モニターは 2 枚以上。Miharikun は別の画面に出しておける
- 実装計画 md は `docs/` 配下。`## [ ] Phase N` か `- [ ]` で進み具合を付ける。依頼は `@docs/xxx-plan.md の Phase 3 を実装して` の形
- 起動は Cursor のターミナルから、exe のフルパスを打っていた

## 便利になったこと
| 困りごと | Miharikun でどうなったか |
|---|---|
| 終わったタブを開いたままだと邪魔。閉じると、作業中・放置・完了の区別がつかない | 状態（自動）とステータス（手動）で分かる。Cursor のタブを閉じてよくなった |
| 何をやっていたか思い出せない | 概要・メモ・3 行サマリー・タイムラインで分かる |
| History で中身を読んで探す | Miharikun の中で探して読める。Cursor でやらなくてよくなった |
| md をリアルタイムで表示するアプリ、プロジェクトの md だけを並べるアプリが無い | ドキュメントタブで解決した |

## 残っている不便と、決めたこと
| # | 不便 | 決めたこと |
|---|---|---|
| 1 | 探すのに 3 段階かかる（左の検索で絞る → カードを選ぶ → タイムラインに同じ語を打ち直す）。どこが当たったかも見えない | 作る（#27）：① 抜粋（検索中のカードに、ヒットした所の前後を出す）② 引き継ぎ（選んだカードのタイムラインに検索語を入れる）③ 強調（タイムラインでヒットした語を強調し、次へ／前へで移る） |
| 2 | 計画 md の Phase が md のどの行か探すのがめんどい。全体の進み具合が一目で見えない | 作る（#28）：ドキュメントタブの拡大モード。「目次｜プレビュー」の 2 列を全幅で出す。目次は見出しの一覧で、`[x]` / `[ ]` を ✅ / ⬜ で出し、押すとその見出しへ移る。通常の画面は今のまま |
| 3 | 起動のたびに exe のフルパスを打っている | コードは変えない（#29）：引数なしならカレントフォルダが対象になる（もともとある機能）。PATH を通して `miharikun` と打つ使い方を README に書く |
| 4 | Cursor のタイトルを手で Miharikun に写している。見つけたチャットを Cursor で開く手段が無い | 受け入れる。下の「事実」を参照 |

## 事実（4 の理由）
- Cursor のチャットのタイトルは `state.vscdb` にしか無い。読まない方針は変えない（壊したときの影響が大きいため。利用者の判断）
- 会話 ID を指定して既存のチャットを開く方法は、Cursor の公式には見当たらない（ディープリンクは新しいチャットを作る方向のものだけ。2026-10-08 時点）
- Cursor の画面を外から自動で操作する方法は、壊れやすく、別の場所へ入力してしまう危険があるので採らない
- Miharikun で探して読めるようになったので、手間は「最後に Cursor で開く一歩」だけに減った

## 保留（使ってみてから決める）
- セッションから計画へのつながり（カードの「📄 plan.md › Phase 3」から、拡大モードでその見出しへ飛ぶ）。目次（#28）を使ってみてから決める
- 左の検索で、AI の返事も対象にする（当たりが増えすぎる心配がある）
- 何日も前のセッションを、カードの引き継ぎ文（タイトル・概要・メモ・変更ファイル・最後の依頼）で新しいチャットにして続ける
- 会社で Claude Code を使えるか（使えるなら、`claude --resume <セッションID>` でカードから再開できる）
