1. ⚙ メニューがドキュメントタブから見えない 要修正

事実：MainWindow.xaml:351-373。⚙ ボタン（Hook・テーマのメニュー）は TabItem Header="ダッシュボード" の中に置かれている。要件 12.7 は「ヘッダー右上の ⚙ メニューに『ドキュメントの設定…』」、12.4.1 も「ヘッダー（タブ・対象フォルダ・⚙）」と、⚙ をタブ共通のヘッダー扱いにしている。計画 15-3 は「⚙ に項目追加」だけなので、ドキュメントタブを開いているときに設定を開けない。

解決：15-1 に「⚙ ボタン（と対象フォルダの表示）を TabControl の外の共通ヘッダーへ移す」を追加。やり方は、Grid.Row="1" に TabControl と同じセルへ HorizontalAlignment="Right" VerticalAlignment="Top" で ⚙ を重ねる（タブ見出しの行の右端に乗る）のが一番手数が少ない。ToolTip も「Hook の導入・削除、テーマ、ドキュメントの設定」に直す。ダッシュボードの拡大モード（12.4.1）の見た目が変わらないか確認する。

2. <base> で #リンクが壊れる・パスの記号が壊れる 要修正

事実：md は preview\{hash}.html に書き出し、<base href="file:///元フォルダ/"> を付ける計画。<base> はすべての相対 URL の基準を変えるので、目次などの [概要](#概要) も file:///元フォルダ/#概要 に飛び、フォルダ一覧（または空ページ）に遷移してしまう。Markdig の UseAdvancedExtensions は見出しに id を付けるので、目次付きの md（要件定義書もそう）で必ず踏む。

解決：

  • MarkdownRenderer が出す HTML に、# で始まるリンクのクリックを横取りしてページ内スクロールする小さなスクリプトを入れる： 
    document.addEventListener('click', e => {
  const a = e.target.closest('a[href^="#"]'); if (!a) return;
  e.preventDefault();
  document.getElementById(decodeURIComponent(a.getAttribute('href').slice(1)))?.scrollIntoView();
});
  • base の URL は自前で文字列連結せず、new Uri(folder + "\\").AbsoluteUri で作る（末尾 / 必須）。テストに「日本語・空白・#・% を含むフォルダ名」のケースを足し、# が %23 になっていることを確認する。html を file:/// で開くときの URL も同じ関数を使う。
  • （代案）一時ファイルと <base> をやめ、WebView2 の WebResourceRequested で仮想ホスト https://doc.miharikun/ にプロジェクトを割り当て、md だけその場で HTML にして返す方式もある。#リンクも相対パスも自然に効き、preview\（会社 md のコピー）も要らなくなる。ただしファイル配信・Content-Type を自前で書くので手数は増える。今回は上のスクリプト案で十分。

3. コードブロックの色付けが計画に無い 要修正

事実：要件 12.7「コードブロックは色付けする」。Markdig は <pre><code class="language-cs"> を出すだけで色は付けない。計画 14-2 は mermaid と CSS だけ。

解決：14-2 に「highlight.js を CDN から読み、language-mermaid 以外の code に適用。テーマ別の hljs CSS（light/dark）も CDN」を追加。mermaid と同じく CDN 前提なので「繋がらないときは色なしのコード」で要件の考え方と揃う。C# で色付けする NuGet（ColorCode 等）は依存が増え、言語の網羅も弱いので選ばない。テストは「class="language-xx" が付く」「hljs の script タグが入る」までを見る。

4. Watcher の穴 要修正

事実：計画は「FileSystemWatcher＋デバウンス＋除外適用」とだけ書かれている。FileSystemWatcher には次の性質があり、素直に作ると索引が黙ってずれる。

起きること素直に作ると「読み直し」ボタンで直るか
docs\ フォルダを丸ごと名前変更・削除イベントはフォルダ1件だけ。中の md の削除イベントは来ないので、ツリーに消えたファイルが残る直る。ただしよくある操作で、ずれても何も出ないので利用者は押す理由に気づけない
npm install・git checkout で大量のイベント内部バッファ（既定 8KB）があふれて Error イベントが来て、取りこぼす直る。同じく気づけない
Filters = *.md, *.html, *.htm を付けるフォルダ名も絞られて、上のフォルダのイベント自体が来なくなる直る（上の 2 つを起きやすくする原因）
node_modules\a\b\c.md が変わるファイル名だけ見ると除外に当たらず、除外したはずのファイルが索引に載る直らない。読み直すと消えるが、npm を動かすたびにまた載る

方針：Watcher はファイルの差分だけ扱い、それ以外は「自動で読み直し」

フォルダ単位の差分（接頭辞で消す・そのフォルダだけ走査し直す）は作らない。ややこしいイベントが来たら、「読み直し」ボタンと同じ全再走査を自動で呼ぶ。全再走査は背景で動き、1万ファイルで数秒なので画面は固まらない。走査中に古い結果が混ざらないことは、5 の世代番号で担保する。

イベント判定動き
Created / Changed / Deletedパスが .md .html .htmファイルの差分として、索引に追加・更新・削除
Renamed古い名前と新しい名前のどちらかが対象の拡張子古い名前を削除し、新しい名前を追加（エディタが一時ファイルを rename して保存する場合もこれで更新扱いになる）
Created / Renamed（新しい名前）Directory.Exists が true（フォルダ）全再走査を予約
Deleted / Renamed（古い名前）拡張子が対象外で、索引にその下（path\ で始まる）のエントリがある＝消えたのはフォルダ全再走査を予約（消えた後なので Directory.Exists では判定できない）
Error（バッファあふれ）―全再走査を予約
フォルダの Changed、対象外のファイル―捨てる（フォルダの Changed は中のファイルが変わるたびに来るため、ここで再走査すると走査が止まらない）
  • 除外の判定（①）は必須：GitIgnoreMatcher に IsPathExcluded(relPath) を足し、a、a\b、a\b\c.md と親フォルダから順に IsIgnored を見て、1つでも当たれば捨てる。走査の枝刈りと同じ結果になることをテストで確かめる。
  • 設定：NotifyFilter = FileName | DirectoryName | LastWrite | Size、IncludeSubdirectories = true、Filters は空、InternalBufferSize = 64KB（あふれにくくする。あふれても再走査で直る）。
  • 全再走査中も、選択中のファイル・ツリーの展開状態・絞り込みの文字は保つ（再走査が勝手に走っても画面がリセットされたように見せない）。
  • テスト：FileSystemWatcher そのものではなく、「イベント → ファイルの差分 or 再走査」の振り分けを純粋関数（例：DocumentChangeClassifier）に切り出して、上の表の行ごとにテストする。実物の Watcher のテストは 1〜2 本に留める（タイミング次第で落ちるため）。デバウンスの書き方は既存の SessionMonitor（Timer）に揃える。

5. 索引の同時更新と、再走査の混線 要修正

事実：走査（背景スレッド）・Watcher（スレッドプール）・画面（UI スレッド）の 3 者が DocumentIndex を触る計画で、所有者が決まっていない。また「保存で即再走査」「読み直し」のとき、キャンセルした前回の走査のバッチがキャンセル後に届いて新しい索引へ混ざる。

解決：

  • 索引を変えるのは1か所だけ：バッチも Watcher の差分も UI スレッドへ Dispatcher.InvokeAsync で送って、そこで DocumentIndex を更新する（Core の DocumentIndex 自体はスレッド非安全でよく、テストが簡単）。
  • 再走査ごとに世代番号を +1 し、バッチに番号を持たせる。現在の世代と違うバッチは捨てる。
  • Watcher は走査より先に開始する（走査中に増えたファイルを拾うため）。索引は相対パス（大文字小文字無視）をキーにした辞書なので、走査と Watcher の両方から同じファイルが来ても重複しない。
  • 画面への反映は 200ms 程度でまとめる（バッチごとにツリーを作り直すとちらつく）。展開状態はフォルダの相対パスで覚えて作り直し後に戻す。

6. Markdig の標準機能を使う 要追記

  • タスクリスト：UseAdvancedExtensions に含まれ、<li class="task-list-item"><input disabled type="checkbox" checked> を出す（大文字 X・入れ子・番号付き・コードブロック内は対象外、も標準の挙動）。自前の置換は書かず、14-1 の 6 ケースは「Markdig の出力の確認テスト」として書く。黒丸消しは CSS .task-list-item{list-style:none} だけ。
  • mermaid：UseAdvancedExtensions の Diagrams 拡張で、```mermaid は <div class="mermaid">（中身は HTML エスケープ済み）で出る。計画の「<pre class="mermaid"> に変換」は自作になるので不要。mermaid.js は .mermaid を見るのでそのまま動く。オフライン時にコードの改行が潰れないよう CSS で .mermaid{white-space:pre}。
  • mermaid にもテーマを渡す（mermaid.initialize({theme: dark ? 'dark' : 'default'})）。
  • 実際の出力の形は、14-1 の最初にテストで固定してから CSS を書く（バージョンで変わり得るため）。

7. テーマ変更の通知が無い 要追記

事実：ThemeService は Mode と Set() だけで、変わったことを知らせるイベントが無い。OS 追従（System）のときは OS の切り替えでも変わる。

解決：16-2 に「ThemeService に event Action<bool isDark> Changed を足す（⚙ からの変更・OS 変更の両方で発火）。DocumentsViewModel は受けたら表示中の md を作り直して再表示」を追加。html は変えない（要件どおり）。

8. リンク遷移の扱い 要追記

WebView2 の NavigationStarting と NewWindowRequested（target="_blank"）の両方で、次の表で振り分ける。決めておかないと、html→html で開いた先が「保存で自動再読込」で元のファイルに戻される等が起きる。

遷移先動き
http / https（mermaid・hljs の CDN 読み込みは遷移ではないので対象外）キャンセルして既定ブラウザ（Process.Start UseShellExecute）
対象フォルダ内の .md / .html / .htmキャンセルしてアプリ内で選択（ツリー・一覧も追従、lastOpened も更新）。html→html も同じ扱いにする
対象フォルダ外の .md / .html、除外フォルダ内キャンセルして既定のアプリで開く（ツリーに無いので）
その他のローカルファイル（pdf・xlsx 等）・フォルダキャンセルして既定のアプリ／エクスプローラー
#xxx だけ（同じページ内）そのまま通す（md は 2 のスクリプトで処理済み）

9. WebView2 の airspace とタブ切り替え 要追記

  • WebView2（WPF）は中身が別ウィンドウ（HWND）なので、同じ領域に重ねた WPF 要素は下に隠れる。「Runtime が必要です」の案内・読み込み中表示・WPF-UI の Snackbar などをプレビューの上に重ねない。案内はプレビュー領域を Visibility で入れ替えて出す。設定ダイアログは別 Window（ShowDialog）にする（ContentDialog のようなウィンドウ内オーバーレイだと隠れる）。⚙ の ContextMenu は別ポップアップなので問題ない。
  • WPF の TabControl は選んでいないタブの中身をビジュアルツリーから外す。走査結果・選択・展開状態は View ではなく DocumentsViewModel に持つ。WebView2 は戻ってきたとき作り直しになり得るので、Loaded で「選択中のファイルを表示」を呼び直す作りにする。16-1 で「タブを行き来しても表示が残る/戻る」を確認項目に入れる。

10. プロジェクト設定の書き方 要追記

  • 同じ JSON に ignore（ダイアログ保存）と lastOpened（選択のたび）が入る。片方だけ持ったオブジェクトで上書きすると他方が消えるので、毎回「読む → 該当キーだけ変える → 全体を AtomicFile で書く」。知らないキーも残す（将来の追加用）。既存の AppSettingsStore と同じく JsonNode で扱う（AOT 互換）。
  • ファイル名のキーは ProjectPath.Normalize(path)!.ToLowerInvariant() を使い、自前で正規化しない（9章のプロジェクト判定と揃う）。AppPaths.ProjectSettingsFile(path) で slug と hash8 を作る。
  • lastOpened が指すファイルが消えていたら復元しない（テストに入れる）。

11〜16. 軽微

11. 走査の書き方 軽微

System.IO.Enumeration.FileSystemEnumerable<T> を使い、ShouldRecursePredicate で除外フォルダを枝刈り、ShouldIncludePredicate で拡張子を絞る。FileSystemEntry から更新日時・作成日時・サイズが追加の I/O 無しで取れるので速い。EnumerationOptions{ IgnoreInaccessible = true, AttributesToSkip = 0 }、ジャンクション/シンボリックリンクのフォルダ（ReparsePoint）には入らない（ループ・別ドライブへの迷い込み防止）。AOT 互換。

12. 性能テスト 軽微

1万ファイルの生成＋時間の assert は、Defender のスキャンや CI の遅さで落ちる。正しさのテスト（件数・枝刈り）は数百ファイルで行い、1万ファイルの時間計測は [Trait("Category","Perf")] にして通常の dotnet test から外す（--filter で明示実行）。

13. Docs プロジェクト 軽微

テストプロジェクトが net10.0 なので Docs も net10.0（-windows にしない）。MarkdownRenderer は「md 文字列＋元フォルダ＋テーマ → HTML 文字列」で完結し、Core を参照する必要がない（計画の「参照：Core」は外してよい）。CSS は EmbeddedResource で、単一ファイル発行でも問題なし。

14. 概要カード 軽微

行数は全文を読むので、数 MB の html で UI が止まる。Task.Run で読み、選択が変わったら破棄する。タイトル抽出は先頭 64KB だけ読めば十分。文字コードは UTF-8 前提で、読めない（Shift_JIS の古い html 等）ときはファイル名にフォールバック。

15. preview ファイルの同時書き込み 軽微

2 つの Miharikun が同じ md を開くと同じ preview\{hash}.html を書く。AtomicFile.WriteAllText で書き、IOException は握ってログ（失敗しても前の内容が残るだけ）。

16. 計画 md の矛盾 軽微

5章のリスク表「要件定義の Phase 13 見出しは、着手時に書き換える」と、6章「要件定義の見出しも書き換え済み」が食い違う。要件定義は既に Phase 13〜17 になっているので、5章の行を消す。
