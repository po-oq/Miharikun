Issue #9 ドキュメントタブ 設計イメージ

ゴール：対象フォルダ配下の .md / .html を、ツリー → ファイル一覧 → プレビューで読む。md は整形表示（チェックボックス・mermaid 含む）、html はそのまま表示（相対リンクの css/js/画像も効く）。1万ファイル超でも軽い。除外するフォルダ・ファイルはプロジェクトごとに gitignore 形式で設定できる。
※この版は、Q1〜Q9 の回答を反映した確定版。

Issue の画像に合わせた構成：①上部に「読み直し」と「パスで絞り込み」（「一覧/ボード」切替は作らない）②ツリー先頭に「すべて」、各フォルダに子孫込みの件数③フォルダ選択で直下のファイルだけを一覧（ファイル名の横に所属フォルダ）④右は「ドキュメント概要」カード＋「内容」カードの2段。md 内のリンクは青字。ヘッダー右上の ⚙ に「ドキュメントの設定…」を追加。

3. 速度（1万ファイル超対策）

ボトルネック対策
全フォルダの再帰走査背景スレッドで EnumerationOptions(RecurseSubdirectories)＋除外パターンによる枝刈り（既定で .git node_modules bin obj 等。ここが最大の効果。プロジェクトごとに調整可）。拡張子で絞るので中身は読まない。目安：1万〜10万ファイルで数百ms〜数秒。走査中も、見つかった分から順次ツリーに出す（画面は固まらない）
2回目以降索引は保存せず、起動時に毎回背景走査。まず実測し、遅ければキャッシュを足す
一覧の描画WPF の仮想化リスト。1フォルダ数千件でも表示は見えている分だけ
検索ファイル名はメモリ上の索引で部分一致（即時）。本文検索はやらない（提案：必要になったら別 Issue。ripgrep 的な全文走査は重い）
変更検知FileSystemWatcher の差分反映。大量変更（git checkout 等）は一定時間まとめて処理

4. 採用した機能のまとめ

ツリーdocs の無いフォルダは出さない／件数は子孫込み／「すべて」の行
一覧選んだフォルダの直下のみ／更新日の降順
絞り込みファイル名＋フォルダ名の部分一致（本文検索はしない）
読み直し手動の全再走査（自動反映の保険）
内容カードのボタン再読み込み／フォルダで開く／既定のアプリで開く
復元最後に開いたファイルをプロジェクトごとに覚え、次回起動時に開く
テーマmd のプレビューはライト/ダークに追従（html はファイルの見た目を尊重）
htmlJavaScript 実行 OK。外部 http のリンクは既定ブラウザで開く
作らない一覧/ボード切替、本文検索、md の編集、索引キャッシュ
