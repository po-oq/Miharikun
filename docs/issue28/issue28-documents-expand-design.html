調査から決めたこと（案）

こと決め方
拡大中の別の mdIssue のとおり。一覧からは「戻す」から選ぶ。md の中のリンク・メモタブの「ドキュメントで開く」で移ったときは、拡大のまま目次を替える
拡大の状態保存しない（起動時は常に通常）。タブを切り替えて戻っても拡大のまま。選んでいたファイルが無くなったら戻す（タイムラインの拡大と同じ）
目次を押したとき押したときに移る（同じ項目をもう一度押しても移る）。保存で目次を作り直しても、プレビューは動かさない
目次に出さない見出し空の見出し。コードブロックの中・生の <h2> は、そもそも見出しにならない。引用・リストの中の見出しは出す
Windows で WebView2 Runtime が無いとき描けないので目次は出ない。拡大はできる（案内が全幅になるだけ）
ページから届く知らせkey:Escape だけを受け、ほかは捨てる（html は利用者のファイルの JS が動くため）。届いても「戻す」だけなので害は無い

Q1. html を拡大するか（Issue の「確かめること」）
A) 拡大できる。目次の列は出さず、プレビューを全幅に … 利点：md のリンクで html に移ったときも同じ形のまま／欠点：特に無し
B) md のときだけ「拡大」を出す。リンクで html に移ったら自動で戻す … 利点：単純／欠点：リンクで勝手に戻って驚く
推奨：A（リンクで移るときの振る舞いが素直）
Q2. 目次に出す見出しの深さ
A) すべて（#〜######）を段で字下げ … 利点：抜けが無い／欠点：見出しの多い md（要件定義は約 100）で長い
B) ### まで … 利点：短い／欠点：深い所へ飛べない
C) 目次の上で切り替え（2 段／3 段／すべて）… 利点：柔軟／欠点：作る量が増える
推奨：A（目次はスクロールすれば足りる。困ったら C を足す）
Q3. 目次の上に進み具合の集計（例：✅ 3 / 6）を出すか
A) 出す。[x]／[ ] 付きの見出しが 1 つ以上あるときだけ … 利点：「全体の進み具合が一目で」に直接効く／欠点：特に無し
B) 出さない
推奨：A
Q4. 見出しでないタスク（- [ ]）の扱い（Issue #7 で、計画の進み具合は ## [ ] Phase N か - [ ] で付けると分かった）

B) 見出しの [x]／[ ] だけ（Issue のとおり）… 利点：単純／欠点：- [ ] 式の計画では何も見えない
推奨：A（会社の計画 md が - [ ] 式なら必須。Q3 の集計は見出しの ✅/⬜ だけを数える）
Q5. 拡大中、上段（読み直し・パスで絞り込み・件数）も隠すか
A) 隠す … 利点：縦が広く使える。上段はツリー・一覧のためのもの／欠点：拡大中は読み直せない（戻せばよい）

5. リスクと対策

リスク対策
Windows（WebView2）では試作 Q1〜Q7 を確かめていないWebView に関わる Phase の後で、Windows の実機で確かめる（Esc・目次で移る・位置の補正）。invokeCSharpAction が入らなければ、独自の URL への移動を NavigationStarted で取り消して受ける形に替える
WebView2（Chromium）にある「幅が変わっても位置を保つ働き」と、こちらの補正が二重に効く補正は「覚えた要素の今の位置との差」だけ動かすので、すでに合っていれば動かない見込み。実機でずれれば、ページで overflow-anchor: none にして補正だけにする
html の iframe の中にフォーカスがあると、Esc が届かない受け入れる（「⤡ 戻す」で戻せる）
html のページの JS が、勝手に invokeCSharpAction を呼ぶkey:Escape だけを受ける。届いても拡大を戻すだけ
ヘッドレスのテストでは WebView を作らないので、目次が来ないVM・画面のテストは目次を直接渡して確かめる。id の一致は Docs のテストで、HTML の id と見出しの一覧を突き合わせる。ページの中の動きは実機で
拡大でプレビューを動かすと、WebView が作り直されて位置もページも失うプレビューは同じ Grid の同じ場所に置いたまま、目次の列を足し、隣を隠す（試作 Q4 で確認済み）
保存のたびに目次が作り直され、目次のスクロールがずれる中身が同じ項目は使い回し、目次のスクロール位置を保つ
反映先：回答をもらったら、要件定義の 12.7 に「12.7.1 拡大モード（Issue #28）」を足し、15 章に Phase 38〜を足す → 実装計画（impl-plan。md と html の対）→ 別セッションのレビュー → 実装（Docs のテスト先行 → ViewModel → 画面 → 両 OS の実機確認）。
