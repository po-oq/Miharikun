Issue #2：セッションに「ステータス」を入れる — 設計イメージ

コード変更前の確認用。決めたい点は最後の「確認したいこと」にまとめた。

1. 何を作るか（1 分で）

  • セッションごとに、ユーザーが手で設定する「ステータス」を持たせる。値は 作業中 / 中断 / 完了（未設定もある）。
  • 設定する場所はセッション詳細（中央）。一覧のカードにバッジを出し、一覧をステータスで絞り込める。
  • 既存の「実行中のみ / 未コミットあり / メモあり」とは別軸。組み合わせて（AND）絞れる。
  • ステータスは自動では変わらない（Cursor のイベントでは書き換えない）。タイトル・メモと同じ「ユーザーが書くメタ」。

2. 用語整理：「状態」と「ステータス」は別物

状態（いまある）ステータス（今回追加）
決める人Miharikun が Hook のイベントから自動判定ユーザーが手で設定
値実行中 / ボスの番 / 中断 / エラー / 閉じた（未設定）/ 作業中 / 中断 / 完了
表示カード左上の色つき丸 + 文字、上部の件数チップカードのバッジ（新規）、一覧の絞り込みタブ（新規）
保存先保存しない（イベントから毎回計算）meta\cursor\{sessionId}.json（新規フィールド）

⚠ 「中断」が両方にある（状態の「中断」＝ユーザーが Stop した、ステータスの「中断」＝やりかけで置いてある）。画面で混ざるので、呼び名を分けたい（→ 確認したいこと①）。

4. 中身の作り（概念図）

保存形式（meta json）

{ "v": 1, "title": "...", "memo": "...", "status": "working" }
  status: 省略（= 未設定） | "working"（作業中） | "paused"（中断） | "done"（完了）
  • 既存ファイルは status が無い＝未設定。バージョンは上げない・移行も不要。
  • 知らない値が入っていたら未設定として扱う（壊れても落ちない）。
  • Core は AOT 互換のまま（enum は文字列と手書き変換。リフレクションなし）。

7. 確認したいこと

  1. 「中断」の名前の衝突：案A ステータス側を「中断」のまま、自動の状態側を「停止」に改名（推奨）／案B ステータス側を「保留」にする／案C 両方そのまま（混ざるのを許容）。
  2. ステータスの種類：Issue 本文は 3 つ（作業中・中断・完了）だが、画像には「未分類／相談中／あとで」もある。本文どおり 3 つ + 未設定で進めてよいか（増やしやすい作りにはしておく）。
  3. 絞り込みの見せ方：画像のようなタブ（件数つき）で進めてよいか。それとも既存のチェックボックス並び（複数選べる）にするか。タブは「1つだけ選ぶ」。
  4. 導入前のセッション（取り込み分）もステータスを設定できるようにしてよいか（推奨：できる）。
  5. 検索の対象に「作業中」などの文字は含めない（絞り込みはタブで行う）でよいか。
  6. 自動連動なしでよいか（例：完了にしたセッションにまた依頼が来ても、ステータスは勝手に作業中に戻さない）。

①〜⑥は「推奨のとおり」で進めてよければ、そう返信してもらえれば要件定義の更新から着手する。
