# Windows 実機の確認の手順（Issue #31・Phase 47-1）

> 実装計画 `docs/security/security-plan.md` の 9.8 の確認表を、Windows（WebView2）で行うための手順。mac は実装するセッションが確認済み（できなかった項目は 3 章）。
> **本物のプロジェクト・本物のデータは使わない。** 試験用のフォルダ（害のないファイルだけ）と、`MIHARIKUN_*` で向けた一時のデータで行う。

## 1. 準備
1. 確認するブランチ（`feature/issue31-security`）でアプリを作る：`scripts/publish.ps1`（または `dotnet build`）。**起動中の Miharikun は止めておく。**
2. 試験用のフォルダを作る：
   ```
   powershell -ExecutionPolicy Bypass -File docs\security\New-SecurityTestProject.ps1
   ```
   `%TEMP%\miharikun-sec-test` にできる（`-Root` で変えられる）。`.bat` は `echo` の 1 行、`.exe` はただの文字。シンボリックリンクは、権限が無ければ作らずに知らせる（開発者モードか管理者なら作れる）。
3. 表示された 3 行で環境変数を一時のフォルダに向け、`proj` をカレントにして `Miharikun.exe` を起動する。
4. 確認の前に、ネットワークにつながっていてよい（ネットなしの確認は 2 章の最後）。

## 3. mac で確認できていない項目（Windows でも、できれば見る）
- Esc（ページの中で押す）が届く／目次で移る／再読み込みの位置の復元が、CSP の下でも動く（計画 9.7 の 2・3）。上の 15・17・18 に含まれる。
- ネットワークのパスの画像で接続が起きない（9.7 の 5）。上の 12。

## 4. 結果の伝え方
- 表の「結果」に ○／×／メモを書いて知らせてください。×の項目は、見えたもの（エラー・出た窓）を教えてください。
- 6 がだめなら、計画 9.2 の代わりの形（名前に `,` を含むときは親フォルダを開く）に直します。
- 後始末：`%TEMP%\miharikun-sec-test` を消す（`.bat` や `.exe` はただのファイル）。
