5. 決めたいこと

Q1. Claude の保険の探索で、別のプロジェクトのログを読む量を減らす方法（#7）
A) フォルダの名前で先に絞る：フォルダ名の英数字だけを取り出した並びが、対象のパス（そのまま・NFC・NFD・実パス）の英数字の並びと同じか、その先頭部分（Claude Code が長いパスを切り詰める版に備える）のフォルダだけを見る。見るフォルダの中は今のまま全ファイルの先頭の cwd を照らす … 利点：日本語・記号の違いで同じ名前になったフォルダでも取りこぼさない。開くのは関係しそうなフォルダだけになり、計画より読む量が減る。欠点：英数字の部分まで違う規則の変化（将来の版）には効かない。小さな関数とテストが増える
B) 計画のまま（新しい順で、cwd が取れた最初の 1 ファイルで打ち切る）… 利点：簡単。欠点：同じ名前のフォルダを共有すると、新しいほうでないプロジェクトの Claude のセッションが全部消える（mac の日本語名で起こりうる）。要件 9.1 の理由の文を「共有するときは取りこぼす」に直して受け入れる
C) 一致したときだけ打ち切る（今と同じ）で、1 フォルダで見るファイルを新しい順に N 個までにする … 利点：取りこぼしが減る。欠点：N の決め方に根拠が無く、全プロジェクトのフォルダを開くのは変わらない
推奨：A（保険がいちばん守りたい「日本語名で規則がずれた」場合を守りつつ、ほかのプロジェクトのログを開く数がいちばん少ない）。A のテスト：英数字の並びが違うフォルダは開かない（ReadFirstCwd を呼ばない）、同じ並びのフォルダに対象と別のプロジェクトが混ざっていて、新しいほうが別でも見つかる、NFD の名前のフォルダが見つかる
Q2. Windows で PATH の UNC の項目（\\server\share\Git\cmd）の git を使うか（#8）
A) 使う（\\?\・\\.\ の形だけ除く。PATH の順は守る）… 利点：今まで見つかっていた git が見つからなくなる環境が無い。PATH は利用者・管理者の設定で、診断 #2 の入口（カレントフォルダ）とは別。欠点：共有に届かないとき File.Exists が待つ（今の CreateProcess も同じく待つ）
B) 使わない（計画のまま）… 利点：ネットワークに触れない。欠点：会社の PC などで git が「不明」になる。app.log の 1 行と要件 13 章への記載が要る
推奨：A（要件 13 章の「PATH の絶対パスの項目」にもそのまま合う。テストに UNC の項目を足し、相対・.・空は今の計画どおり使わない）
